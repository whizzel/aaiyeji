# Aaiyeji — digital invitation studio

**A beautiful way to say, you’re invited.**

Marketing website and live invitation-demo showcase for Aaiyeji, a studio that
creates personalised digital invitation websites for weddings and life’s
special celebrations. Built with Next.js (App Router), TypeScript and Tailwind CSS.

This first release is an **enquiry/conversion website** — no checkout, no
accounts, no backend. The content architecture is data-driven so a future
template system/CMS can plug into `lib/` without rewriting pages.

## Quick start

```bash
npm install
npm run dev        # http://localhost:3000
```

Other scripts:

```bash
npm run build      # production build
npm run start      # serve the production build
npm run typecheck  # strict TypeScript check
npm run lint       # ESLint (next/core-web-vitals + typescript)
```

## Routes

| Route | What it is |
| ----- | ---------- |
| `/` | Homepage: hero, live-demo showcase, occasions, features, Royal spotlight, process, packages, trust, FAQs, enquiry form |
| `/demo/royal` | “The Heritage” — royal heritage wedding sample (Hindi + English, personalised welcome via `?to=Family+Name`) |
| `/demo/floral` | “The Garden” — soft garden wedding sample (Marathi + English) |
| `/demo/minimal` | “The Modern” — minimal city/coast wedding sample |
| `/sitemap.xml`, `/robots.txt`, `/opengraph-image` | SEO routes generated by Next.js |

Demo invitations include a welcome gate, bilingual toggle (where included),
family introductions, ceremony timeline, venue + map link, live countdown,
gallery, **clearly-labelled demo RSVP (nothing is sent or stored)**, share /
copy-link / add-to-calendar (.ics), and a music control that explains the
tap-to-play feature (no audio is bundled — nothing licensed is available yet).

Try the Royal personalisation: `/demo/royal?to=Sharma%20Family`.

## Environment variables

Copy `.env.example` to `.env.local`. **All variables are optional; never commit
real values.** The site behaves honestly when they are unset:

| Variable | Purpose | Format |
| -------- | ------- | ------ |
| `NEXT_PUBLIC_SITE_URL` | Canonical URL, metadata, OG, sitemap | `https://your-real-domain.com` (no trailing slash) |
| `NEXT_PUBLIC_WHATSAPP_NUMBER` | WhatsApp CTAs + enquiry form destination | Country code + digits only, e.g. `9198XXXXXXXX` |
| `NEXT_PUBLIC_CONTACT_EMAIL` | Contact link in the footer/enquiry section | Real company email |
| `NEXT_PUBLIC_INSTAGRAM_URL` | Footer social link (shown only when set) | Full profile URL |

Enquiry form behaviour:

- WhatsApp configured → the form opens a prefilled `wa.me` chat (visitor presses
  send) to the number in `NEXT_PUBLIC_WHATSAPP_NUMBER`.
- WhatsApp not configured → shows a clear “not configured” message with a
  copy-to-clipboard action. It never pretends an enquiry was sent.
- Email is a separate contact link; it is not used as a form fallback.

## Where things live

```
app/                    Routes, layout, global styles, SEO (OG image, sitemap, robots)
components/
  layout/               Header (accessible mobile nav), footer
  home/                 Homepage sections (hero, showcase, pricing, FAQs, enquiry…)
  invitation/           Shared invitation template (gate, hero, timeline, RSVP, countdown, share)
  ui/                   Buttons, container, headings, logo, motifs, reveal
lib/                    Single sources of truth: site-config, pricing, occasions,
                        invitation-demos (typed schema), features, trust, validation, utils
brand-assets/           ★ Brand source of truth (editable masters + guidelines)
public/brand-assets/    Runtime copies served by Next.js (keep in sync — see brand-assets/README.md)
public/images/demos/    Original SVG gallery artwork for the demos
```

### Editing business facts

- **Prices, features, add-ons, delivery times, revisions:** `lib/pricing.ts` only.
- **Occasions:** `lib/occasions.ts`.
- **Demo invitations:** `lib/invitation-demos.ts` — add a typed record and its
  gallery artwork; the route and homepage showcase pick it up automatically.
- **Brand colours:** `brand-assets/brand-tokens.css` (+ `design-tokens.json`),
  imported by `app/globals.css`. Never hardcode brand colours in components.

### Brand assets

`brand-assets/` holds the logo system (wordmark, symbol, favicon), patterns,
OG cover master, tokens and guidelines. All assets are **initial concepts** the
company can replace after formal brand approval. See `brand-assets/README.md`
for usage, sync commands and status.

## Honesty rules baked into the build

- No invented testimonials, statistics, discounts, contact details or domains.
- Tax note: “Final quote and applicable taxes, if any, will be confirmed before booking.”
- Delivery timing starts after all required details/assets are received and confirmed.
- Rush delivery is capacity-dependent, never guaranteed.
- Demo RSVPs are demonstrations — nothing is sent or stored.
- No analytics/tracking until a real provider and privacy disclosure exist.
- Music never autoplays; no copyrighted audio is bundled.

## Before launch

1. Set the real environment variables (`.env.local` / hosting settings).
2. Replace the concept logo if formal brand artwork is approved.
3. Add real, approved testimonials to `lib/trust.ts` (structure is ready).
4. Optionally bundle licensed audio for the demos’ music feature.
5. Run `npm run typecheck && npm run lint && npm run build`.
